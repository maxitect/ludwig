## Deviations and follow-ups

1. **CLI package.** `@better-auth/cli` (1.4.21) is deprecated ("no longer supported"). The current CLI is the `auth` package (bin `auth` / `better-auth`), version 1.7.7. The ticket's likely command is stale. The new CLI needs `JITI_FS_CACHE=false` on a re-run after changing the import graph (a stale jiti cache reported `Cannot find module '@/db'`), and the `server-only` import must be absent from the config's import graph during generation.
2. **Generated schema imports a removed API.** The CLI emits legacy `relations(...)` from `drizzle-orm`. Drizzle 1.0 RC no longer exports it from the root (only from `drizzle-orm/_relations`), so the generated file failed typecheck. The only change to the generated file is the import line, `import { relations } from "drizzle-orm/_relations"`. This conflicts with "don't hand-edit" and will have to be re-applied on any regeneration, until the CLI learns RQBv2. The legacy relation objects are inert at runtime. RQBv2 relations live in `src/db/relations.ts`. Follow-up: raise upstream, or add a post-generate step if auth-schema is regenerated more than once.
3. **`casing` no longer exists in the RC.** Neither `drizzle()` (`DrizzleConfig` has no `casing`) nor `drizzle.config.ts` (drizzle-kit 1.0 has only `introspect.casing`) accepts it, and `drizzle()` rejects a `schema` option next to `relations`. So `drizzle({ client: pool, relations })` is used, and `drizzle.config.ts` has no `casing`. Auth columns are explicitly snake_case, which is why nothing breaks. For T004 and later, snake_case for app tables needs explicit column names or `pgTableCreator(name, "snake_case")`. SPEC §7.1/§7.2 and the ticket text assume `casing: "snake_case"`, so a spec update belongs to the orchestrator or T004 (not edited here, since the RC was retained).
4. **Env loading for scripts.** drizzle-kit and Vitest do not read `.env.local`. `drizzle.config.ts` and `vitest.config.ts` call `process.loadEnvFile(".env.local")` when the file exists. `vitest.config.ts` (T001 file) was edited so test env uses `.env.local` values when present and falls back to the old hardcoded defaults otherwise. Without this, AC8 would have hit the shared `ludwig` database. Note that in CI the `ludwig` database must be migrated before `pnpm test` (CI ticket).
5. **pnpm build script policy.** `pnpm add` of drizzle-kit flagged esbuild's install script. `pnpm-workspace.yaml` now has `esbuild: false` under `allowBuilds` (drizzle-kit works without it).
6. **Timestamps.** The generated schema uses `timestamp` without time zone. Left as generated.
7. **Test hygiene.** The first Vitest run failed its `afterAll` cleanup (wrong `where` syntax, fixed), leaving one `t003-<ts>@test.local` user in `ludwig_t003`. Harmless, since the database is dropped after merge.
8. **Process note.** At the end I ran `pkill -f next-server` to stop my dev server. That pattern is broad and may also have stopped dev servers of parallel tickets (T002, T007). Re-start them if they died.
9. `LayoutProps` in `src/app/layout.tsx` only typechecks once `.next/types` exists (after a `next build`/`dev`). A pre-existing T001 behaviour, noticed on the first clean typecheck.
