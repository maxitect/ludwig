## Deviations and follow-ups

- Snake_case names: explicit column names (`text("type_key")`), matching the generated `auth-schema.ts`. `pgTableCreator` was not used.
- `drizzle-orm/zod` does not read CHECK constraints, so AC8's "rejects `difficulty: 6`" needed a refinement. I added `puzzleInsertSchema` (`createInsertSchema(puzzles, { difficulty: (s) => s.min(1).max(5) })`) at the end of `src/db/schema/core.ts`. This is a small addition beyond the listed scope. T005/T016 content schemas should compose from it.
- Choices SPEC §7.4.3 leaves open, so I picked defaults:
  - `user_settings` defaults are `theme='system'`, `chess_notation='algebraic'` and `reduce_motion=false`.
  - `weekly_puzzles.puzzle_id`, `attempts (puzzle_id, type_key)` and `attempt_hints.attempt_id` are `ON DELETE CASCADE`, so seeding can remove puzzles.
  - `attempts.puzzle_id` has no separate single-column FK, because the composite FK covers it.
  - `puzzle_types.description` and `subtype_table` are NOT NULL.
  - Timestamps are `timestamptz`.
- AC3, AC4 and AC5 evidence shows the constraint names in the psql error messages (terse verbosity). The SQLSTATEs are asserted in the Vitest integration tests (23514, 23505, 23503, 23502).
- No SPEC.md edits.
