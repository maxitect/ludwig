## Deviations and follow-ups

- **Test DB wiring.** `vitest.config.ts` now points `DATABASE_URL` and `DATABASE_URL_UNPOOLED` at `<db>_test` for all tests, so existing tests (T003 `db.test.ts`, T004 `core.test.ts`) also run there and the dev DB is never touched. `global-setup.ts` creates and migrates it once per run. The admin URL is passed through `INTEGRITY_ADMIN_DATABASE_URL`, set in the config.
- **Test users** use the Better Auth API (`auth.api.signUpEmail`), which works from Vitest. No adapter rows are inserted.
- **AC7 behaviour:** the trigger overwrites. If the puzzle does not exist, it keeps the supplied value so the composite FK still raises `23503` (tested).
- **T004 tests changed (required by the new triggers).** In `src/db/schema/core.test.ts`: the "pins type_key" test expected `23503` for a wrong key and `23502` for a missing key; both now succeed because the trigger fills the value, so it now asserts that. The cascade test commits a puzzle, which now needs a subtype row, so it creates and drops a `cxa_puzzles` table.
- **REVOKE.** Only `REVOKE ... FROM PUBLIC` is applied. `anon` and `authenticated` roles do not exist on plain local/Neon Postgres, and the `/db-trigger` skill is Supabase-specific.
- SPEC §7.4.5 describes `attempts_fill_type_key` as `BEFORE INSERT`; the ticket specifies `BEFORE INSERT OR UPDATE OF puzzle_id`. The SPEC was not edited (out of scope); the orchestrator may want to align it.
