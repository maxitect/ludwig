## Deviations and follow-ups

- **AC4 literal curl grep.** `curl ... | grep 'data-theme="ink"'` finds nothing. Under Cache Components the root layout cannot read the session or cookies without losing the prerendered shell (AC3), so `<html>` carries no per-user attribute. Following the Next "preventing flash" guide, an inline script in `<head>` (first HTML response, `ac4-first.html`) reads the `theme` cookie (signed in) or `localStorage` (signed out) and sets `data-theme` before paint. A `ThemeSync` client component mirrors the DB theme into the cookie for new devices, and re-applies after strict-mode remounts. Signed-in persistence is `user_settings` via `saveTheme` (upsert); the cookie is a client-readable mirror.
- Theme menu offers Paper, Ink and System. Signed-out users get a Sign in link plus a theme icon dropdown; the signed-in menu trigger shows the display name.
- Removed `SignOutButton` (replaced by the menu item) and the Sign up link in the header (still on the sign-in page).
- Toaster not mounted globally: the kitchen-sink coverage test requires that page to own the `sonner` import, and the shell has no toasts. A save failure shows an inline alert in the menu instead.
- Added `src/app/icon.svg` (ink square, red L; raw hex because it is an asset) and removed the `data:,` favicon workaround from kitchen-sink.
- Font credits link points to Google Fonts (no credits page exists); cburnett attribution links CC BY-SA 3.0 and Wikimedia Commons. Wording is mine, SPEC §10.2 gives none.
- Next keeps the previous route hidden (Activity), so two `<header>` elements exist in the DOM after a client navigation; one is `display: none`.
- Home page token test sheet deleted as the starter content; `/dev/kitchen-sink` covers it.
- Not in scope and noted: nav links have no active state.
