## Deviations and follow-ups

- **Contract has two extra members** beyond `{ schema, load, loadSolution, check, Solver, meta }`: `insertContent(tx, puzzleId, content)` (the per-type writer for subtype and child rows, which the seed needs) and optional `verify(content)` (throws on failure). `check` returns `{ correct: boolean }` only; `cellsWrong` from SPEC 4.1 is left for T017 because its type needs a decision.
- **`meta` is `{ key }`** (derived from `puzzleTypes.$inferSelect`); nothing else was specified.
- **Content file shape** is `{ meta, content }` (SPEC 4.6; PLAN 5.4 says `{ meta, payload, solution }`, which looks stale). `meta` is `puzzleInsertSchema.pick({ slug, title, difficulty, sourceNote, publishedAt }).extend({ volume })` with the volume given by slug. `meta.slug` must equal the file name.
- **CLI flags** `--registry <module>` and `--content-dir <dir>` on both scripts let the fixture registry run from the CLI (AC6). Defaults are the production registry and `content/`.
- **Scripts run via `tsx --conditions react-server --env-file-if-exists=.env.local`** so `server-only` imports from type modules resolve outside Next.
- **Fixture DDL** (`src/puzzles/__fixture/ddl.ts`) is applied in `src/db/integrity/global-setup.ts` after migrations (small edit to a T005 file).
- **Seed behaviour:** a failing or invalid file never deletes its existing puzzle (its slug counts as discovered). "updated" means rewritten; there is no change detection. Node caches dynamic imports per path, so tests use a fresh temp dir when rewriting a file.
- **Lookups content** (names, descriptions, three volumes `pocket-collection-1..3`) are placeholders I wrote; review wording. `pictogram_glyphs` is out of scope (no table yet).
- `pnpm typecheck` in a fresh worktree fails on `LayoutProps` until `next build` generates types (pre-existing).
