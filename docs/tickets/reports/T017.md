## Deviations and follow-ups

- **Registry contract gained `replaceAttemptState(tx, attemptId, state)`**, the "module's attempt writer" the ticket relies on. Fixture implements it with a new `__fixture_attempt_rows` table (DDL in `ddl.ts`); the fixture `attemptSchema` changed to `{ rows: [{ position, value }] }`.
- **`cellsWrong` / check result shape unsettled.** `check` still returns `{ correct: boolean }`; actions pass the module's result through unchanged (`{ ok: true, result }`). Needs a SPEC decision when the first real type lands.
- **`checkAnswer` options** are `{ mode: "full", durationMs } | { mode: "cell", row, col }`. `durationMs` is not in the ticket signature but is required to complete an attempt. Cell mode uses the same module `check` and only records a `check_cell` hint; per-cell correctness is type-specific and has no module hook yet. Same for `revealCell`: it only records the `reveal_cell` hint and returns `{ ok: true }`; a module `reveal` hook is needed to return the cell value.
- **Action contract:** returns `{ ok: false, error: "invalid" | "not_found" }` for bad input or unpublished puzzle; unauthenticated calls throw (`requireUser`). The ticket says `saveState(puzzleId, ...)` while SPEC 4.3 says `attemptId`; followed the ticket (attempt resolved from the session user).
- **AC6 nuance:** choosing the type's schema needs the puzzle's type key, so `getPublishedTypeKey` (a read) runs before the answer/state schema check. Structural validation (uuid, options) happens first with zero data access; no attempt write happens before validation.
- **Extra data helpers** in `puzzles.ts`: `getPublishedTypeKey` and `checkPuzzleAnswer` (loads payload and solution server-side, keeps actions thin). "Published" means `published_at` not null and not in the future.
- **No revalidation** is performed: nothing cached depends on attempts yet; the Casebook/stats tickets should add tags.
- **`vitest.config.ts`: `fileParallelism: false`** added, since the new test and `scripts/seed.test.ts` both use the `__fixture` type and clean it up in the shared test database.
- Tests mock `@/lib/auth` `getSession` (below `getCurrentUser`), not `getCurrentUser` itself, because `requireUser` calls it within the same module.
