## Deviations and follow-ups

- Reveal: no reveal-all action exists (T017 only has `revealCell`) and solutions never reach the client. Confirming the dialog therefore shows "Reveal is not available for this puzzle yet." and records nothing. A per-type reveal needs a decision and an action in a later ticket.
- Restoring saved state: `initialState` is always `null`. No data function loads an attempt's saved state, and the ticket does not list one. `onStateChange` autosaves (800 ms debounce) through `saveState` when signed in. Signed-out players save nothing (T020).
- `__fixture` `Solver` is now a real client text-input solver (`src/puzzles/__fixture/solver.tsx`). It is not registered in the shipped registry. The gears and reverse-chess modules now have `Solver: null` (type `SolverComponent | null`), and the solve page shows "not open yet" for them.
- `generateStaticParams` for `[type]/[slug]` returns all puzzles including unpublished ones, because Cache Components requires at least one param and there are zero published puzzles. The page itself still 404s on unpublished slugs (verified in the production build).
- "Next in volume" orders by slug within the volume across types, because `puzzles` has no position column.
- `published` is now exported from `src/lib/data/puzzles.ts` for reuse in `catalogue.ts`.
- The Solver props contract matches `.claude/rules/puzzles.md` (no rules edit needed).
- `cellsWrong` was not needed.
- Vercel preview checks are recorded in the PR.
