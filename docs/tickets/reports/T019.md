## Deviations and follow-ups

- **`loadAttemptState` added to `PuzzleTypeModule` (planned deviation).** `loadAttemptState(attemptId)` mirrors `replaceAttemptState`: it returns the state parsed by the type's `attemptSchema`, or null when none is saved. It is required on the contract and implemented for every registered module (anagram, reverse-chess, gears, rota) and for `__fixture`.
  - gears, reverse-chess and rota use new RQBv2 relations in `src/db/relations.ts` (`gearAttempts.swaps`, `reverseChessAttempts.plies`, `rotaAttempts.swaps`).
  - `getAttemptState(userId, puzzleId, typeKey)` in `src/lib/data/attempts.ts` finds the user's attempt and calls the module loader. The solve page calls it inside the session `Suspense` and passes `initialState` to `SolveChrome`, which now takes an `initialState` prop and passes it only on the first mount (`Reset` remounts with null).
  - Tests: `src/lib/data/attempts.test.ts` (own and other user's state), `src/puzzles/load-attempt-state.test.ts` (reverse-chess, gears and rota round trips on committed data), `anagram/tables.test.ts`.
  - Reset does not clear the saved server state, so a reload after Reset restores the old arrangement.
- **Enter-to-check lives in `SolveChrome`.** AC8 needs Enter to check, and Check is a chrome button. The Solver wrapper in `solve-chrome.tsx` handles `Enter` when the target is not a button, link or input. The anagram board is auto-focused on mount and refocused after each tile click.
- **`load.ts` reads the answer through `loadSolution`.** The tiles are a scramble of the answer (SPEC §7.4.4: "tiles derived from the answer and seed"), so the payload cannot be built without it. `load.ts` never selects the column itself and never returns it. `payloadSchema` carries `definitionHint`, `tiles` and `wordLengths`. This slightly stretches `.claude/rules/puzzles.md` ("load never selects (S)"), so the rule may want a note for derived-from-solution payloads.
- **The solver uses plain `<button>` elements, not `ui/Button`.** The registry is imported by `db:seed` and `puzzles:verify` under tsx with `--conditions react-server`, and radix (`Slot`) throws `React.createContext is not a function` there. Shuffle and Clear copy the Button secondary-small classes. If more solvers need `Button`, the scripts or the registry import graph need a fix.
- **Uniqueness.** `verify` proves the tiles are a permutation and not the answer. There is no dictionary, so "exactly one anagram" is by authorship; the five answers (`bridge`, `lantern`, `cathedral`, `ink and paper`, `retrograde analysis`) have no common alternative anagram. The `words` lookup is word-ladder scope.
- **Saved answer** stores letters only, no spaces, in `anagram_attempts.answer`. Spaces and case never count in `check`.
- **Seed range.** `scramble_seed` is `integer` with a `>= 0` check (mulberry32 accepts it); the SPEC row doesn't state a type.
- `cellsWrong` was not needed. Solved state is not restored on reload (a solved puzzle shows unsolved, as for the fixture in T018).
- Migration: `drizzle/20261002225028_anagram_tables` (no triggers needed: the generic `puzzles_require_subtype` and `attempts_fill_type_key` already cover the new type). The `anagram` lookup row already existed in `content/lookups.ts`.
