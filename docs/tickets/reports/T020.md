## Design notes

- Client-safe attempt schemas: `src/puzzles/attempt-schemas.ts`, a small map of `attemptSchema` imported straight from the `anagram` and `crossword` `schema.ts` files (the types that have solvers). Add a line when a type gets a solver.
- Store: `src/utils/local-progress.ts`. Entry and merge Zod schemas: `src/lib/forms/local-progress.ts` (cap `MAX_MERGE_ENTRIES = 200`).
- Merge logic: `mergeLocalProgress` in `src/lib/data/attempts.ts`. Server Action: `src/lib/actions/merge.ts`. Entries with an unknown puzzle, a mismatched type or an invalid state are skipped.
- Trigger: `LocalProgressMerge` client component rendered by `UserSlot` when signed in, so it runs after sign-up or sign-in (both redirect into the app layout). Keys are cleared per merged batch.
- Signed-out `checkAnswer` full mode only checks. Cell mode signed out still throws `Unauthorised`. SolveChrome keeps the sign-in notice for cell check and reveal only (text now "to check or reveal individual cells").
- Signed out, the solver renders after hydration (Walker until then) so the local state is the initial state.

## Deviations and follow-ups

- Fixed `readStoredTheme` in `src/utils/theme.ts` to catch storage errors. With `localStorage` throwing, `ThemeSync` crashed the whole page (AC6 failed in cycle 1). Outside the ticket's listed files but required by AC6.
- Local completion carries `startedAt` over (earliest wins) so `duration_ms` stays consistent with `started_at` and `completed_at`.
- Review follow-up (needs a decision, not fixed): per the ticket, `mergeLocalProgress` trusts the client's claim that a local entry is complete, so a signed-in user can mark any published puzzle solved (with any `started_at`) without passing `checkAnswer`. It only affects the user's own Casebook stats (T023 views read `completed_at`/`duration_ms`); there are no shared leaderboards. Verifying would need a per-type state-to-answer mapping.
