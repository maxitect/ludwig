## Deviations and follow-ups

- drizzle-kit emitted the three `CREATE VIEW` statements in alphabetical order, which fails because `user_category_stats` and `user_streaks` select from `user_solves`. I reordered the statements in the generated migration (before it was ever applied or committed); `pnpm db:generate` reports no further schema changes.
- "Current streak" is 0 when the latest solve day is before yesterday in London. A streak survives until the end of the day after the last solve. This is a view decision the ticket did not specify.
- Views are `pgView(...).as(sql...)` in `src/db/schema/progress.ts`, so drizzle-kit owns them; future edits to a view need a regenerated migration.
- `/casebook` is dynamic (session read behind `<Suspense>`, no `use cache`), so a fresh solve shows immediately. No tags added.
- Account theme for Ink screenshots was set with a `user_settings` insert through psql (not a user/account insert).
- `src/lib/data/casebook.ts` reads the session-less `userId` passed by the page; the page calls `getCurrentUser()` and redirects to `/sign-in` if absent.
