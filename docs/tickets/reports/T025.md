## Deviations and follow-ups

- **`attempts` gained `unique (id, type_key)`** (`attempts_id_type_key_unique`, in `src/db/schema/progress.ts` and this ticket's migration). The `<type>_attempts` composite FK `(attempt_id, type_key) -> attempts(id, type_key)` needs a unique constraint on exactly those columns, and T004 only created `(id, puzzle_id, type_key)`. SPEC §7.4.3 updated to list it. Every later type's attempt subtype needs this same constraint, so it is already in place.
- **Enum placement:** `chess_file`, `chess_piece`, `chess_colour` are in `src/db/schema/core.ts` (shared with Rota); `retro_mode` and `retro_special` are in the type's `tables.ts`, since only this type uses them.
- **Column names** (SPEC lists "four castling-right bools" without names): `white_kingside`, `white_queenside`, `black_kingside`, `black_queenside`.
- **`ply_count` is not in `contentSchema`.** It is derived at insert as `solutionPlies.length`, so the two cannot drift. Solution plies get `ply` from array position (1-based), also not in content.
- **`ply` and `attempt_id`/`puzzle_id`** are omitted from the content, answer and attempt row schemas. Rank bounds 1-8 are also enforced in Zod (the `CHECK` stays in the DB).
- **`check` is a placeholder that throws** (`check.ts` and the real check belong to T029 per its scope). `Solver` is a null placeholder as specified. No `verify` hook yet (T027); until then `puzzles:verify` passes and `dev-rook-check` is not yet proved unique.
- **Registry entry** lives in `src/puzzles/reverse-chess/module.ts` (same pattern as the fixture type) and is added to `src/puzzles/registry.ts`. The `reverse-chess` `puzzle_types` row already existed in `content/lookups.ts`, so it was not changed.
- **FK constraint names** are set explicitly for the three single-column child FKs, because drizzle-kit 1.0.0-rc.4 otherwise generates random names.
- Relations added in `src/db/relations.ts` for `reverseChessPuzzles` (`pieces`, `solutionPlies`).
- The leak test commits one puzzle to the test database and removes it (and the lookup rows it added) in `afterAll`.
