## Deviations and follow-ups

- **chess.js 1.4.0 was not in `package.json`**; added with `pnpm add chess.js@1.4.0` (the stack lists it, the engine needs it).
- **Position and prior are FEN strings.** The ticket fixtures are FENs, and chess.js consumes them directly. T027/T029 call `toFen(...)` from `derive.ts` to get one.
- **`Retro` is a small new type in `engine.ts`** (`from`/`to` as chess.js `Square`, `uncapture` as chess.js `PieceSymbol`, `unpromote`, `special` from `SolutionPly["special"]` minus `"none"`). The DB-shaped `SolutionPly` uses file/rank columns, so it cannot be used directly; T027/T029 need a conversion. Please confirm or redirect this type.
- `uncapture` accepts any `PieceSymbol` so `'k'` can be rejected at runtime as the AC requires.
- Prior position choices: halfmove 0; fullmove derived from the position; en passant target only set for `special: 'en_passant'`; for castling only the castled side's right is added to the prior (other rights unchanged).
- A malformed castle (not a king `e1/e8` to `g/c`, or no rook beside it) returns `replay_mismatch`; an occupied rook home square or en passant captured-pawn square returns `origin_occupied`; an uncapture combined with en passant returns `illegal_uncapture`. The ticket's reason union has no better fits.
- Unpromote rank check: the promotion rank of the moving side (rank 8 for White, rank 1 for Black).
