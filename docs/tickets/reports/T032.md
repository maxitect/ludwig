## Deviations and follow-ups

- Authoring method: each puzzle is the end of a proof game generated and replayed in chess.js, then verified with the repo verifier. Searches and generator scripts live in the git-ignored `.verification/t032/`.
- Castling cannot be made unique in Mode A (a king or rook un-move such as Kh1-g1 or Re1-f1 always survives), so castling and en passant appear in Mode B, where the goal forces the un-castle or the un-en-passant. Both are two-ply puzzles.
- The three T025-T030 dev fixtures moved to `src/puzzles/reverse-chess/fixtures/` because three Vitest files import them; they are no longer content.
- The hub's "How it works" gained an Unwind subsection (Mode B copy).
- Flow 3 drags with the mouse on desktop and with CDP touch events on the mobile project; the drag is wrapped in `toPass` and waits for Undo to enable, since a drag before hydration is ignored. The first run after a cold dev compile failed once, then 14 further runs passed.
- No DB polling is used for the wait; the flow waits on the UI result, so it also works on previews where `databaseAvailable` is false.
