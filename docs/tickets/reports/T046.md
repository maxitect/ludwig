## Deviations and follow-ups

- **`check` returns `{ correct, wrongCells }`** (AC4 asks for the wrong cells). Wrong cells are rule-based (a digit repeated in a row, column or box, an empty cell, or an overwritten given), not a diff against the solved grid, so the checker never reveals which cells differ from the solution. The `checkAnswer` action and the chrome still read only `correct`; showing the wrong cells in the UI is not wired.
- **`checkCell` and `revealCell`**: the spec does not say what they mean for sudoku. Implemented against the solution derived by `loadSolution` (the givens solved by the engine, unique by `puzzles:verify`). The solver does not yet use the Check cell and Reveal cell buttons, because the ticket does not ask for them.
- **CellGrid extended** (T021's shared piece, crossword unchanged): optional `direction`/`onDirectionChange` (no advance, no Space toggle), `readOnly` cells (labelled "given", ink display font), `cellClassName`, `marks` (decoration behind the value), `inputMode`, Delete as erase, and `words={[]}` lets Tab leave the grid. Tests added in `cell-grid.test.tsx`. Futoshiki (T047) can reuse all of it.
- The grid is checked automatically when the last cell is filled by typing (`requestCheck`), so a keyboard-only solve needs no Check press. The Check button still works.
- Mirrored digits: static `mirrored-digits` utility in `globals.css` (SPEC §6.3), applied to the solver wrapper.
- Content: five generated-then-curated puzzles (`first-light` 40 givens ... `dead-end` 25 givens), difficulty by given count. All proven unique. The generator was a throwaway script, not committed.
- SPEC §7.4.4 sudoku row updated (checks, derived solution, `wrongCells`).
- Migration `20261005182334_sudoku` only creates five tables; backward compatible. The screenshots are in `.verification/t046/` (lower case).
