## Decisions (docs silent, recommended option taken)

- `rung_count` is the number of rungs **between** the fixed start and end words. The answer is the whole ladder (start, rungs, end), so an endpoint mismatch is checkable. Recorded in SPEC §7.4.4.
- A ladder may not reuse a word (reported as `repeated`).
- `check` returns `rungProblems: { position, reason }[]` (`not-a-word`, `not-one-step`, `repeated`) so the solver can mark invalid rungs after Check. They depend only on the answer and the dictionary. To carry it, `checkAnswer`'s result type, `SolverProps.rungProblems` and `solve-chrome.tsx` (stores the last result, clears it on Reset) gained one optional field. SPEC §7.4.4 notes it.
- `loadSolution` returns every dictionary word of the ladder's length (about 7.5k strings for 6 letters), so the module's synchronous `check` stays pure. Fine at checkAnswer frequency. (Review: the reference rungs were dropped from it, since nothing checks against them.)
- `word_ladder_attempt_rungs.word` has no FK to `words` (it holds what was typed, partials included) and no cascade concerns. Only `word_ladder_puzzles` and `word_ladder_solution_rungs` point at `words`, with no cascade, and words are never removed.
- `words` table lives in `src/puzzles/word-ladder/tables.ts`; the word wheel can import it.
- `puzzles:verify` reads `content/words.txt` lazily from `process.cwd()` (`dictionary.ts`, only reached via `verify`). The build showed no tracing warning.

## Dictionary source and licence

SCOWL (Spell Checker Oriented Word Lists), Kevin Atkinson, via npm `wordlist-english` 1.2.1 (the package's MIT licence covers only its JavaScript; the lists carry SCOWL's notices). The package is not a dependency; it was used once to generate the file. `english` and `british` lists at frequency levels 10, 20, 35, 40, 50, 55, keeping only all-lowercase `a-z` 3 to 6 letter words (drops proper nouns, hyphenated and accented forms). 15322 words (3: 634, 4: 2438, 5: 4736, 6: 7514). SCOWL's full Copyright file is reproduced verbatim in `content/words.COPYRIGHT` (it includes the VarCon, Ispell and WordNet notices the British list requires) and summarised in the header of `scripts/seed-words.ts`. `hmm` is the only interjection spotted; the list is not otherwise curated.

## Seed time

`scripts/seed-words.ts`: one `INSERT ... ON CONFLICT DO NOTHING` per 5000-word batch (review round 1 removed a redundant `select`). Local Postgres, `words` emptied first: whole `pnpm db:seed` (15322 words and every content file) 1.07 s; with the words present 0.94 s. Expect more on Neon over the network (4 batches, 8 round trips for words), still small against the build. The seed only inserts; it never deletes words.
