## Decisions (docs silent, recommended option taken)

- Nothing is **(S)**: the lines are the puzzle and the message is derived from them by the rule, so `loadSolution` derives it and `check` compares. No message column exists.
- The payload is `{ ruleLabel, lines }`. The rule key stays on the server; the label is a fixed text per rule (`RULE_LABELS` in `derive.ts`). The S1E1-style "first letter of each sentence" is `first_letter_line` with one sentence per line.
- The message is the upper-case letters A to Z of the derived characters (case, accents, spaces and punctuation ignored); a line or word with no letters adds nothing, and `puzzles:verify` rejects letter-free lines and messages under 4 letters.
- The answer input is a single plain text field, so `LetterTiles` and `RungInput` were not reused: the message length is not given to the player (and the tiles need a fixed length). `CellGrid` was not used.
- Attempt state is the typed text (at most 80 characters, a CHECK and a schema limit). `acrostic_attempts` has no `puzzle_id`, as no child table references content, so there is no deferred FK or fill trigger and `pnpm db:generate` reports no changes after the generated migration.
- Added `acrostic_puzzles.lines` relation, `acrostic` registry, solver and attempt-schema entries, and updated the SPEC §7.4.4 acrostic row.
