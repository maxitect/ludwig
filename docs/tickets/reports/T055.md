## Decisions (docs silent or in tension, recommended option taken)

- **`check` returns `{ correct, wrong }`.** AC4 requires the count of wrong roles, while the handover said not to add per-type extras. The AC wins; `wrong` is a number only, like logic-grid's `wrongPairs` and sudoku's `cellsWrong`, so T131 can fold it into the unified field. The UI does not show it.
- **Predicates are authoring metadata.** `contentSchema` carries a typed `claim` per statement (`is`, `same`, `different`, `all` and `any` over those three, `atLeast`, `exactly`). It is never stored or sent. The verifier tries all 2^n assignments, needs exactly one, and needs it to equal the stored roles. A knave's statements must all be false. No SPEC question was needed.
- **Attempt tables follow word-search.** `knights_knaves_attempts` has a trigger-filled `puzzle_id` and `knights_knaves_attempt_roles` has `puzzle_id` plus a deferred, non-cascading FK `(puzzle_id, character_position)` to the characters, hand-edited into the generated migration. `db:generate` reports no changes afterwards. The two redundancy cases are in SPEC §7.4.5. Triggers are in the custom migration `knights_knaves_triggers`.
- **Solver state is partial roles.** The player may leave characters undecided, so `attemptSchema` is a list of `{ position, role }`. The registered answer is `null` until every character has a role.
- **Shared component** `src/puzzles/_shared/statement-list/statement-list.tsx`: speakers with their statements and one native radio group each, generic over the option values so T056 and T057 can reuse it. A chosen option shows a tick as well as a fill. The accessible group name is the speaker plus the question.
- SPEC §2.3 (the type's row), §7.4.4 and §7.4.5 updated. No SPEC §1.2 change.
- No `puzzle_types` lookup change was needed, the row already existed.
