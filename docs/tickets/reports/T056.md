## Decisions (docs silent or in tension, recommended option taken)

- **Explanation delivery.** `check` returns `{ correct, epilogue }` with the explanation as `epilogue` only when correct (the existing rota mechanism). No new action or response field. After a reload of an already solved puzzle the epilogue is not re-fetched, as with rota.
- **`reviewNote` plumbing.** The ticket puts it in `meta`, which `contentMetaSchema` would strip. `scripts/content-files.ts` now parses an extended file meta, hands `reviewNote` to `verify` as a second argument (`verify(content, { reviewNote })`, also in `time-verify.ts`), and strips it from the `meta` that `db:seed` writes. Other types' `verify(content)` are unaffected.
- **Tables.** Solution FK `(puzzle_id, item_position)` is immediate and non-cascading. `odd_one_out_attempts` has a trigger-filled `puzzle_id` (custom migration `odd_one_out_triggers`) and a deferred, non-cascading FK `(puzzle_id, item_position)` to the items (hand-edited into the generated migration; `pnpm db:generate` reports no changes). `unique (puzzle_id, label)` is `DEFERRABLE INITIALLY DEFERRED` so labels can swap on a reseed. The item count of 4 to 5 is enforced by `contentSchema` and verify, not the database.
- **Shared statement list not reused.** It models speakers with statements and per-speaker choices; odd one out is one choice among items, so the solver is a single native radio group instead.
- SPEC §2.3, §7.4.4 and, because the redundant `puzzle_id` must be listed there (SPEC rule 2, `.claude/rules/database.md`), one row in §7.4.5.
