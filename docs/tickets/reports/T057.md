## Decisions

- The answer input is a text field with `inputmode="decimal"`, not `type="number"`, so the value is exact text and never a float. `answerSchema` is `/^-?\d{1,12}(\.\d{1,6})?$/` after a trim. Leading zeros and trailing zeros are valid ("04", "4.0").
- AC2 reading: "4.01" is a valid decimal, so it is a wrong answer (`correct: false`). "four" is the validation error. Both are rejected without a crash.
- `answer` is `numeric(18,6)` on both the puzzle and the attempt. `check` compares `normaliseDecimal` strings (`decimal.ts`), so no float is involved. The attempt stores the last valid decimal; an invalid or empty field saves `null`.
- `meta.workings` follows the odd-one-out `reviewNote` path: `content-files.ts` strips it, and `verify(content, { reviewNote, workings })` receives it. The registry `authoring` type, `verify-puzzles.ts` and `time-verify.ts` were updated, and SPEC sections 2.3, 4.6 and 7.4.4 now describe it.
- The attempt table references no content row, so it needs no puzzle_id, trigger or deferred FK. Only the generated migration `20261009125009_napkin_maths_tables` was added (no custom trigger migration).
- `puzzle_types` already had the `napkin-maths` row in `content/lookups.ts`. The weekly schedule is untouched.
