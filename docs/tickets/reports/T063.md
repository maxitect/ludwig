## Deviations and follow-ups

- **Content:** five original puzzles in `content/rota/`: Night Shift (1), Scaffold Row (2), The Building Site (3, modelled on S1E4 with new names), Canteen Queue (4), The Long Shift (5). Generated from the solution backwards by a seeded search that keeps only clue sets giving a unique shortest sequence. `weekly.ts` untouched.
- **`verify` hook** (`src/puzzles/rota/verify.ts`, registered in the module): checks `solve` returns exactly the stored sequence (unordered pairs, in order), every worker has both zones, the two rotas use the same zones, no two workers share a zone, and the instigator is in the first swap, and a `max_swaps` clue caps the sequence below its length + 2 (by parity no longer sequence then satisfies every clue). Tests in `verify.test.ts`.
- **`check` now also returns `violatedClue`** (position of the first broken clue, computed from the payload and the answer only), and `brokenClues(payload, swaps)` is shared with the solver. Required by AC3 ("naming the clue"). No engine change.
- **Stack order:** the stack is persisted in forward order (the newest unswap is forward step 1), so the saved rows mirror the solution swaps. The board starts at the final rota; clues are evaluated in the browser once everyone is back on the intended rota and broken ones are marked "Broken".
- **Opening gambit (user decision 2026-10-07):** the instigator is no longer part of the answer. `answerSchema`, `attemptSchema`, `check` and the solver lost it, and the picker is gone. `check` returns `epilogue` ("Opening gambit: <name> insisted on it.") only for a correct answer, shown by `SolveChrome` in the solved footer; the payload is unchanged (leak test still passes). `rota_solutions.instigator_worker_id` and the `verify` step-1 check are kept. `rota_attempts.instigator_worker_id` stays nullable and is no longer written; a later migration ticket can drop it. SPEC §5.1, §7.4.4 and the ticket AC3 updated.
- **Board:** a purpose-built 8x8 board (`board.tsx`) using the T028 paper/ink square colours, not `ChessBoard` (that component is piece and chess.js oriented and has no token or pencil-line support). Tokens are buttons (tap, keyboard) and also HTML5 draggable (desktop).
- **SPEC:** §5.1 Mode C example clue reworded to "No more than 5 swaps were made"; clue meanings, shortest-sequence uniqueness, instigator rule and solver behaviour recorded.
- **Hub:** a minimal "Mode C / The Rota" section with a "Play The Rota" link added after the mode lists (rebased on main after T043).
- `prettier` is not a project dependency; content files were formatted with `pnpm dlx prettier` (object entries stay on one line).
- No migration.
