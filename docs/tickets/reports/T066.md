## Deviations and follow-ups

- Mechanism: React starts a view transition only when a named `<ViewTransition>` is in the changed tree, and a ViewTransition placed in a page did not fire when navigating between the `(marketing)` and `(app)` layouts. So `BulletHoleTransition` (empty fixed `ViewTransition`, with `onEnter` marker) sits in both group layouts, links use `transitionTypes={["bullet-hole"]}`, and the tear animates the root snapshot. React sets `view-transition-name: none` on `<html>`, so the CSS forces `root` back on with `!important` only while the `bullet-hole` type is active.
- Cross-layout transitions use `:active-view-transition-type()`; browsers without it get no animation (graceful).
- Landing links in `title-sequence.tsx` and `desk.tsx` gained `transitionTypes`; `BulletHole`/`BulletHoleTransition` were added to the kitchen sink (coverage test). `SolveChrome` change is two lines. SPEC.md not edited.
- The torn polygon keyframes in `bullet-hole.css` were generated once by a script (not kept).
