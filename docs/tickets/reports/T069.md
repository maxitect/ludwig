## What was slow and what changed

Lantern (Lighthouse's simulated throttling) scores the bytes and requests before the first paint, so the work was cutting the first load and the layout flips.

- **Drizzle and zod were in the shared client bundle.** `utils/local-progress.ts` statically pulled every puzzle's attempt schema (and so every table). It now keeps a cheap shape check for writes and loads zod and the schemas on demand when saved progress is read or merged. 1.19 MB to 0.80 MB of first-load JS on the landing page.
- **SolvedStamp (motion) was in the brand barrel.** Removed from the barrel and loaded with `next/dynamic` in the solve chrome.
- **Every solver shipped on every solve page.** `src/puzzles/solvers.ts` is now `solvers.tsx`, a client map of `next/dynamic` solvers, so a page ships the one solver it renders. `SolveChrome` resolves its solver from `typeKey` (the page no longer passes it). SPEC section 4 and `.claude/rules/puzzles.md` updated.
- **Radix menus out of the first load.** The theme menu, account menu, mobile nav sheet, solve-page puzzle menu and the crossword clue sheet load after hydration through a small `Deferred` helper (a stand-in button is shown, and a press before the code arrives opens it on arrival). It deliberately does not suspend: a `Suspense` boundary here delayed hydration of the whole page by about 600 ms (measured: Check button hydrated at 670 ms versus 75 ms on main), which broke about 50 e2e specs.
- **Solvers now render on the server for signed-out players** (the Walker used to stand in until a `useSyncExternalStore` flag flipped), so the content is in the first HTML. Local progress is read after mount and swaps the solver's initial state if an entry exists; saves are ignored until that read completes so an empty mount cannot overwrite it.
- **`use cache` on the play payload** (`getPuzzleForPlay`, `cacheLife("minutes")`, tag `puzzles`) so the dynamic part of the solve page no longer waits on the payload query.
- **Fonts:** Dancing Script (only the Solved stamp uses it), Barlow, Caveat Brush and JetBrains Mono are no longer preloaded. The timer text renders after mount, so the mono font is not requested on the first paint.
- **Layout shifts on phones:** the book cipher, keyword, caesar and pictogram solvers decided their phone layout in JS after hydration (CLS 0.59 on the book cipher). They now use the `touch:` CSS variants for the default phone layout, with a JS override only for the device-keyboard and hardware-key cases.
- **Walker (the known per-frame layout):** `walker-cross` animated `left`, and the SVG legs animated a transform inside the SVG, which Chrome lays out every frame. The figure now travels with `translate` and `100cqw` (the root is a size container) and each leg is its own element with a composited transform. Layout count on the landing page over 3 s: 25 before, 0 after (CDP `LayoutCount`, also with reduced motion). T140's wall animation already used only transform, opacity and clip-path.
- **Reduced motion** still has the one switch: the Walker keeps its `prefers-reduced-motion` and `:root[data-reduce-motion]` rules.
- `pnpm perf:lighthouse` added (Lighthouse 13 and chrome-launcher as devDependencies; run through `node` because tsx's esbuild injects `__name` into the page-side code).

## Why AC2 and AC4 are not fully met

The remaining misses are bound by design, not by a leftover bug:

- **crossword (87):** the largest text is the clue bar, which lives in `SolveSlot` and is a portal created after hydration, so LCP waits for hydration under the 4x CPU slowdown.
- **pictogram-cipher (87):** prefilled hand letters and the cipher text need Caveat Brush (52 KB) and JetBrains Mono (40 KB) before the first paint; fonts requested before FCP count against the simulated score.
- **reverse-chess (85) and the landing page (89 to 92):** the board and landing sequence code add JS before LCP.

Ideas that would close them, each larger than this ticket: render the slot contents on the server; subset Caveat Brush and JetBrains Mono to Basic Latin (needs a font tool that is not installed here); split the Radix Tabs in `ClueTabs`. A deploy-side check on Vercel (real CDN, brotli, HTTP/2) will likely score higher than this local Node server.
