## Design

- Contract: `insertContent` renamed `upsertContent` (registry, 5 modules, fixture, tests, `.claude/rules/puzzles.md`, `/new-puzzle-type` skill, SPEC §4.6 and §4.2 registry line).
- `upsertPuzzle` no longer deletes the subtype row. It wraps the write and rethrows an FK violation from update/delete on a table with "attempt" in its name as `<type>/<slug>: content change removes a row that attempt data references (<constraint>)`. The per-puzzle transaction rolls back, so the DB is unchanged.
- Upserted on natural keys, stale rows deleted: puzzle subtype rows, gears (puzzle_id, label), rota workers (puzzle_id, name), rota clues (puzzle_id, position; deleted and recreated if the kind at a position changes), rota solution, gear solution, crossword cells and clues (composite pk).
- Child tables with no id and no attempt reference are deleted and re-inserted: gear meshes and solution swaps, rota worker squares, clue subtype rows and solution swaps, crossword clue segments, reverse-chess pieces and solution plies. The ticket asked for upsert everywhere; I deviated here deliberately. These rows are unreferenced and have no ids to stabilise. Rota squares have a non-deferrable unique on (phase, square) that swapping rows would violate mid-statement.
- Gears: the previous driver is unset before the upsert (partial unique index on the driver), and only when the driver label changes.

## Audit: attempt children that reference content rows

| Type | Attempt references to content | Protection now |
|---|---|---|
| anagram | none | nothing to protect, no child rows |
| reverse-chess | none (attempt plies reference only `attempts`) | seed never wrote attempts; solution plies and pieces are unreferenced |
| gears | `gear_attempts.accused_gear_fk`, `gear_attempt_swaps` gear_a/gear_b FKs to `gear_puzzle_gears` (no cascade) | gears keyed by label, ids stable; removing a referenced gear fails the seed |
| rota | `rota_attempts.instigator_fk`, `rota_attempt_swaps` worker_a/worker_b FKs to `rota_workers` (no cascade) | workers keyed by name, ids stable; renaming or removing a referenced worker fails the seed |
| crossword | `crossword_attempt_cells_cell_fk` to `crossword_cells` (deferred, no cascade) | cells upserted in place; removing a filled cell fails at commit, caught and named |

No migration needed. No FK from content to attempt data cascades.

## Deviations and follow-ups

- Removing a puzzle whose content file is gone still runs `delete from puzzles`, and `attempts.puzzle_id` cascades from `puzzles`, so saved attempts of a deliberately removed puzzle are deleted. This is out of scope. Consider whether removal should be blocked when attempts exist.
- Workarounds kept as they are: `db:seed` still spares puzzles linked in `gear_daily`, and gen-gears still skips dates that exist. Both would be safe to relax now but I left them untouched.
- The tests use the real registry with lookups inserted under a temporary `t072` category in the test DB and removed afterwards.
- The orchestrator's rebase onto T023 brought a `casebook.test.ts` that called `insertContent`; renamed.
