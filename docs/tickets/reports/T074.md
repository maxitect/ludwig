## Design

- Column `crossword_clue_segments.separator` of enum `segment_separator` ('word', 'hyphen'), nullable, no default: the break after the segment.
- Deferred constraint trigger `trg_crossword_clue_segments_last_has_no_separator` (insert, update, delete) rejects a separator on a clue's last segment (ERRCODE 23000).
- Null before the last reads as a word break, so a previous-deploy insert that omits the column stays valid (PLAN §5.1). A NOT NULL default would have put a separator on every last segment.
- Content: optional `separators` array on a clue (one fewer than `segments`, refined in `contentSchema`); omitted means all word breaks. Payload segments are `{ length, separator }`.
- `upsertContent` keeps the T072 pattern (segments deleted and reinserted); it writes 'word' for non-last segments and null for the last.

Design judgement:

- Nullable `separator`, no default, NULL on the last segment enforced by the deferred trigger: accepted. Non-last NULL and 'word' both mean a word break, which is two spellings of one fact, but requiring NOT NULL before the last would make any build of pre-T074 code fail its seed (`vercel.json` runs `db:migrate && db:seed` on every build) against a Neon branch that already has this migration: previews of tickets branched before this merge, and any rebuild of an older commit. That is the PLAN §5.1 previous-deploy case, so the tolerance is required for now. The only writer in this PR (`upsertContent`) always writes 'word', and `deriveEnumeration` reads both the same. Follow-up for the orchestrator once no pre-T074 branch can build: backfill NULL to 'word' and extend the trigger to require a separator on every non-last segment.
- A 'word' default would put a value on every last segment, which the trigger must reject, so dropping the ticket note's "keep the default" is right; content-side, omitting `separators` still means word breaks, which is what the note asked for.
- Migrations: one generated (`CREATE TYPE`, nullable `ADD COLUMN`, additive only) plus custom trigger migrations, `SET search_path TO ''`, schema-qualified, ERRCODE 23000.
- AC3/AC5: all 7 multi-segment answers are two-word phrases (RED TAPE, BLUE BLOOD, ICE CREAM, BRASS BAND, EGG CUP, NINE LIVES, HARD CASH), so "hyphen rows where the content has them" is correctly 0 and the content needs no separators. AC3's hyphen render was shown through the real load path with a ticket-DB-only row; accepted as evidence of the mechanism, no grid refill.
- SPEC §7.4.4 crossword row matches the schema and trigger.
