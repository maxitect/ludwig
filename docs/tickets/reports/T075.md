## Deviations and follow-ups

- Check calls `flushSave()` without awaiting it, immediately before `checkAnswer`. Next queues Server Actions in order, so the save lands first.
- Unload saves go through the Server Action, with no `sendBeacon`. A hard tab close mid-request is not guaranteed to complete; `visibilitychange` to hidden normally fires earlier and the request completed in 56 ms. A hard tab close was not tested.
- Reset also drops the pending state so a cleared attempt is not re-saved.
