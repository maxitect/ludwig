## Evidence

Technique (all exact):
- `enumerateRetroSteps` yields each retro move with its prior, so `goalChains` no longer re-runs `applyRetro`; an `admit` hook tests the built prior before validation and replay.
- Leaf level checks `satisfiesGoal` on the built prior first; inner levels skip priors in the barren memo (position key = first 4 FEN fields, plus moves left) or whose `minRetroMoves` bound exceeds the moves left.
- `goal-bound.ts`: admissible bounds. piece_count uses the gap with parity of own/opponent moves (pawn counts and king never fall; non-pawn counts rise only by uncapture, fall only by unpromote). castling_right needs a retro castle plus king walk (rights are only ever added by a retro castle). piece_on_square takes the min of piece distance, uncapture (only if material could host the piece; `materialPlausible` extracted from the engine, and promotion budget never frees in retro play) and unpromotion (pawns below 8).

Timings (middlegame `r1bq1rk1/pp2bppp/2n1pn2/2pp4/3P1B2/2PBPN2/PP1N1PPP/R2Q1RK1 b - - 0 8`, exhaustive enumeration of all chains, no limit):

A goal that most chains already satisfy gains little (the output is the cost). Verification uses limit 2, so these are worst cases.

The old search on this sparse fixture is already under 1 s, so the new bound mostly shows on denser positions.

Timing test: unit test with a 5 s bound (about 25x margin over measured), no separate benchmark script.

`stepRetro`/`enumerateRetro` agreement: regression probe in `goal-chains.test.ts` brute-forces every from/to/uncapture/special combination on 5 positions and asserts each accepted move is enumerated.

## Deviations and follow-ups

- Pruning cannot beat the output size: goals that thousands of chains satisfy stay slow at depth 3+ when listing everything; verify stops at 2 chains.
- Realistic N=6 puzzles need near-frozen positions: any mobile non-pawn piece with optional uncapture multiplies chains, so uniqueness fails (authoring note for T032).
- Local Postgres container had stopped mid-run; restarted with `docker start ludwig-db-1`.
