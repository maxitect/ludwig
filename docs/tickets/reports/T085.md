## Deviations and follow-ups

- **SPEC edits.** §4.6 gains a "Chess positions are authored as FEN" bullet, §5.1 Mode A and the §7.4.4 chess-problem row mention the `fen` content field, and §2.4 `chess-problem` says how the solver and `check` split the work.
- **Shared FEN code.** `toFen`, `fromFen` and the new `fenSchema` moved from `reverse-chess/derive.ts` to `src/puzzles/_shared/chess-fen.ts` (second type needs them); `derive.ts` re-exports them so existing imports are unchanged.
- **Content typing.** Reverse Chess `contentSchema` is now a transform, so `Content` is the parsed shape and `ContentFile` (`z.input`) is the authored one. Reverse Chess tests and fixtures that used a content file as parsed data now call `contentSchema.parse`; four fixtures (`dev-*`) were converted to FEN too. `enPassantFile` is now always present (null) on the parsed shape.
- **Black's reply runs in the browser.** The solver calls the pure `defence` from `engine.ts`, so the client never receives or computes a key move; `check` re-solves on the server. A wrong first move is only caught at the end of the line: `check` returns the failing ply as a `wrongPart` (`wrongPartSchema = { ply }`), which the solver turns into "That doesn't force mate." (ply 1) or "That move doesn't give mate.". The solver requests the check itself once the line is finished.
- **Shared board.** `ChessBoard` gains an optional `onMove` prop for forward play (moves are reported A to B, the retro drop reports B to A). The board stays interactive while Black's reply is pending, because dropping `tabIndex` lost keyboard focus after each reply; the solver ignores moves out of turn instead.
- **Content.** The five problems were found by a randomised search and checked with `puzzles:verify`; `the-corner-office` has two mating second moves (allowed by SPEC §2.4). `content/chess-problem/REVIEW.md` records the lines.
- **Migration** `drizzle/20261020224237_chess_problem_tables` is additive (new tables only).
- **Tests kept lean.** Engine tests run in about a second; the DB tests add one subtype and two puzzles.
- No `preview: true` in the ticket frontmatter, so no preview deploy; nothing in the ticket needs one.
