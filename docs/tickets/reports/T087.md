## Deviations and follow-ups

- Migration `star_battle_tables` is additive (enum, four tables, FKs) and backward compatible. No triggers: SPEC §7.4.4 leaves `size²` cells and `size` regions to `puzzles:verify`, so a missing cell or region is not caught by the database (tested as such).
- `SPEC.md` is unchanged. Section 2.4 says N is 5 to 10; the five files are 6×6, 8×8, 8×8, 9×9 and 10×10.
- The solver is its own grid (like sightlines) rather than `CellGrid`, because tap must cycle empty, dot and star and the star and dot are drawn glyphs. It uses the shared `regionBorderClasses`, and the preview uses the shared `RegionBorders`. `solver.tsx` is allowlisted for `bg-paper` in `raw-tokens.test.ts` so the grid stays paper in Ink.
- A star that touches another or overfills a unit is framed (dashed) and red live in the solver, using the same `conflictingIndexes` as `check`; the check is requested when the last star is placed. `check` ignores the solution because uniqueness makes any rule-abiding full placement the solution, and returns `wrongParts`.
- Content was authored by a throwaway generator (random connected regions, kept when `countSolutions` is 1); it is not committed.
- Added `e2e/star-battle.spec.ts`, `starBattleMarks` in `e2e/helpers/db.ts` and `star-battle` in the axe type list.
