## Deviations and follow-ups

- Migration `circle9_tables` is additive (four tables, FKs, CHECKs). No triggers: the generic subtype-row trigger covers the new `puzzle_types` row.
- Engine for T110: `src/puzzles/circle9/engine.ts` exports `layoutOf`, `solutions(layout, limit)`, `countSolutions`, `solve` and `clashingIndexes`. A layout is `{ digits }`, 81 entries, 0 for empty. The search is exact cover over 36 slots (digit, row, column, box) choosing the slot with the fewest free numbers, so uniqueness checks take about 1 ms. `verify.ts` exports `numbers(content)` and the grid format is nine strings of `1-9` or `.`.
- `check` ignores the stored solution (none exists): any nine circles that obey the rules are correct since `puzzles:verify` proves uniqueness. `wrongParts` names circles on empty cells and circles that share a digit, row, column or box.
- The solver reuses `RegionMarkGrid` with the nine boxes as regions, which gained two optional props, `cellContent` and `cellLabel`, for the printed number and its label. Tap, Space, Enter or C circles; Backspace clears; an empty cell cannot be circled. Clashing circles are framed live in red, as in norinori. SPEC §4 keyboard bullet now notes Circle9 needs no pad.
- The type description credits James Dewar (circle9puzzle.com) in `content/lookups.ts`. The five puzzles were authored by a throwaway generator (a random one-per-row/column/box solution, then random decoy numbers added while the count stays 1), not committed.
- Added `e2e/circle9.spec.ts`, `circle9Circles` in `e2e/helpers/db.ts` and `circle9` in the axe type list.
