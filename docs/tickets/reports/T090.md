## Decisions

- **Answer and completion.** The answer is the target word. The solver sends each word to the new `submitWheelWord` action (`src/lib/actions/word-wheel.ts`, `src/lib/data/word-wheel.ts`), which checks fit and dictionary on the server and stores an accepted word for a signed-in player. When the action says the word is the target, the solver registers `{ word }` and calls `requestCheck`, so the existing `checkAnswer` path completes the attempt with the timer's duration. `check` is `answer.word === target`.
- **Saved state.** The solver also reports `{ words }` through `onStateChange` (needed for signed-out `localStorage`). `replaceAttemptState` therefore keeps only words that fit the attempt's wheel and are in the dictionary, so `saveState` cannot store a word the action would have refused.
- **Payload.** `centre`, `rim` (the other eight letters in a mulberry32 order from the seed), `minLength` and `thresholds` (a third, a half, two thirds of the valid words, rounded down). `load.ts` finds the valid words with one SQL query (length, letter class and centre) then `validWords`; nothing is stored. The player sees the thresholds, so the total is roughly inferable; the word list is never sent.
- **Puzzle id in the payload.** The solver needs the puzzle id for `submitWheelWord`; like spot-difference and cctv-maze, the payload carries it (review change; the earlier optional `SolverProps.puzzleId` was reverted).
- The dictionary grew from SCOWL by raising the same filter from 3 to 6 to 3 to 9 letters; `words_word_check`, `wordPattern`, the seed message, the SPEC and the ladder's "too long" test (`headersxxx`) follow. Word-ladder behaviour is unchanged (its dictionary lookup is by length).
- Content: five wheels (night-wheel, hospital-run, flat-hunt, take-off, dead-hours), original titles that do not echo the words; four use minimum length 4 and one uses 5. `dead-hours` fails at 5 (only 9 valid words), so it uses 4.
- The migration folder is `drizzle/20261021030321_word_wheel_tables`, renamed in review to match the other migrations. It has never run on Neon; local databases that applied it under the generated name need `update drizzle.__drizzle_migrations set name = '20261021030321_word_wheel_tables' where name = '20261021030321_silly_zodiak'`.
- The palette has no green, so nothing uses colour for state: the centre tile is solid ink with a larger size, messages are text. No `bg-paper` was needed, so no allowlist entry.

## Dictionary seed

`words` went from 15322 to 46337 rows (31015 inserted, 10 batches of 5000, `INSERT ... ON CONFLICT DO NOTHING`). A full `pnpm db:seed` against local Postgres with the words already present took 1.4 s.

Review timing of `seedWords` alone on a fresh local database (`.verification/T090/seed-timing.txt`):

```
cold 3-6 only (15322 rows): 102 ms
upgrade to 3-9 (31015 new of 46337): 226 ms
warm 3-9 (0 new of 46337): 172 ms

```

On Vercel the words step is 10 statements instead of 4, so about six more round trips to Neon plus roughly 0.4 MB of parameters. The last production build (`ludwig-grtcexoz8`, `vercel inspect --logs`) spent 158 s in migrate and seed (00:13:44 to 00:16:22). That time goes on the per-puzzle upserts: the build runs in iad1 and Neon is in eu-west-2. So the larger dictionary adds well under a second.
