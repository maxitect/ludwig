## Notes

- Migrations `sudoku_killer_xv_tables` (additive) and `sudoku_killer_xv_triggers` (deferred constraint triggers `trg_sudoku_cages_require_cells` on cage insert and `trg_sudoku_cage_cells_keep_cage_filled` on cell update or delete).
- Tables carry extra CHECKs: cage index 0 to 80, and an XV mark must stay inside the grid (`right` needs col <= 7, `down` needs row <= 7).
- Payload gains optional `cages: [{ sum, cells }]` (cage id is the array index) and `xv: { marks }`. An XV set with zero marks is valid (negative rule only).
- Engine: `Variant` (cages and XV pairs) is an optional 4th argument of `conflictingIndexes`, `enumerateSolutions`, `countSolutions` and `solve`; `variantFor(content)` builds it. Cages prune with a precomputed reachable-sum table and per-cage digit masks. `check` flags every cell of a cage that repeats, passes its sum, or is full and off it, and both cells of a broken or unmarked-but-5/10 XV pair.
- `upsertContent` now also handles a puzzle with no givens (killer with no givens; previously `not in ()` was invalid SQL), and deletes and reinserts cages and XV marks (no ids, no attempt references).
- UI: cage outline is `CageOutline` (dashed, inset, `underlay` prop added to `DigitGrid`), the sum is the cell annotation of the cage's first cell, XV glyphs use the existing `edges` slot. `CellGrid` annotation with null content now only contributes its label. `border-ink` allowlisted for `sudoku/cages.tsx`.
- Content: killers `cage-match`, `dead-sum` (givens), `safe-house` (no givens); XV `x-marks-the-spot`, `roman-numerals`; generated backwards from random solutions by a throwaway script (not committed).
- `puzzles:grade sudoku` still grades with the classic technique ladder only, so it is not meaningful for the five new files; do not run it with `--write`. Their difficulty is hand-set.
- e2e must run against `pnpm dev`: e2e sign-ups are only verified in development. In dev, the Next dev badge covers key "1" of the on-screen pad, so `e2e/sudoku-mobile.spec.ts` "solved by tapping" times out locally (classic puzzle, unrelated to this change; the badge does not exist in production).
- `dead-sum` has no browser screenshot or e2e run (it was added to the spec after the last browser run); it is verified by unit tests and `puzzles:verify`.
- SPEC already described the tables and rules, so no SPEC edit was needed.
