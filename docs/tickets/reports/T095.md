## Deviations and follow-ups

- **SPEC §7.4.4 (kakuro row) edited:** it now states the clue shape (`direction, row, col, length, sum`, positioned at the black cell before the run), that every run needs an on-grid black cell before it, the verify rules, and that `check` returns only `{ correct }`.
- **Marking a wrong run is client-side.** A full run whose sum is wrong or that repeats a digit is framed ("breaks a rule") from the clues alone. `check` has no `wrongParts`, so it is not a solution oracle, and it never says which cell differs from the stored digits.
- **`CellGrid` gained an optional `block(row, col)` prop** (drawn inside a block, with its label read after "block") for the clue cells' split triangles. Other types are unchanged.
- **Content generation:** `scripts/dev/gen-kakuro.ts` is a one-off authoring tool (seeded layout, extreme-leaning fill, local search until `countSolutions` is 1). The 10x10 file needed `MAX_RUN=3 MIN_FRACTION=0.5`; the default settings did not finish in hours at that size. The five puzzles are carbon-copy (6x6), ledger-lines (7x7), cross-purposes (8x8), running-total (9x9) and long-division (10x10).
- Migration `drizzle/20261023173823_kakuro_tables` is named descriptively already.
- Preview is a plain `MiniGrid` of the white cells (no clue numbers).
- Krypto-kakuro stays out of scope.
