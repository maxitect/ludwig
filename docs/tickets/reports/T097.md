## Deviations and follow-ups

- Migration `norinori_tables` is additive (enum, four tables, FKs) and backward compatible. No triggers: SPEC §7.4.4 leaves full coverage and region shape to `puzzles:verify`, so a missing cell or a one-cell region is not caught by the database (tested as such).
- `SPEC.md` is unchanged. The tables use `rows` and `cols` (5 to 12) as the spec says; region names are written in content as base 36 digits, since a 10×10 can need more than 10 regions.
- The five files are 6×6, 7×7, 8×8, 9×9 and 9×9: no 10×10 file, because the throwaway generator did not find a unique 10×10 in reasonable time. The ticket asks for sizes 6×6 to 10×10, so a 10×10 can be added later (T102/T109 style generators).
- The solver is its own grid like star battle's, with the tap cycle empty, shade, dot. It uses the shared `regionBorderClasses`, and the preview the shared `RegionBorders`. `solver.tsx` is allowlisted for `bg-paper` in `raw-tokens.test.ts`. Keyboard model identical to star battle: arrows, `s` shades, `.` dots, Backspace clears, Enter or Space cycles.
- A shaded cell with two shaded neighbours, or in a region holding three, is framed and red live, using the same `conflictingIndexes` as `check`. A lone shaded cell is flagged only by `check` (the check is requested when the last cell is shaded), since it is legitimate while the player is still building a domino. `check` ignores the solution because uniqueness makes any rule-abiding full shading the solution, and returns `wrongParts`.
- Content was authored by a throwaway generator (planted non-touching dominoes, grown regions, boundary moves until `countSolutions` is 1); it is not committed.
- Added `e2e/norinori.spec.ts`, `norinoriMarks` in `e2e/helpers/db.ts` and `norinori` in the axe type list.
- Local `ticket:setup` failed first on `branch rename failed` because `.git/logs/refs/heads/ticket` did not exist in the shared git dir; creating that directory fixed it.
