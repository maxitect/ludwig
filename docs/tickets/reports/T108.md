## Design

- `src/puzzles/sudoku/generate-regions.ts`: generators `sudoku-jigsaw` and `sudoku-rainbow`, version 1, seeded through `generateGraded`. Registered in `src/puzzles/generators.ts`; classic `sudoku` v1 is untouched.
- Jigsaw layout: start from the boxes, apply 400 random exchanges (a cell passes to a touching region, a cell passes back), keeping both regions edge-connected. Growing regions from seeds got stuck every time, so this replaced it. Rejected: a region with a bounding box thinner than 2 or longer than 6, and a layout equal to itself under a half turn or transpose. Then a random solved grid for the regions by backtracking, then single givens removed in shuffled order while the grader (held to the target) still solves.
- Rainbow layout: a random solved classic grid, then groups from a random Latin square (box by group gives a digit), so each group has one cell per box and each digit once, and the grid solves by construction. Rejects symmetric layouts; a group cannot lie in one line, since it meets every box.
- Grader (`grade.ts`): region-based locked candidates already came from T084 (pointing, box/line over regions). Added the law of leftovers for jigsaw (level 4: n lines against n regions, the cells in one but not the other hold the same digits). Rainbow needs no new technique: pointing and box/line already run over the colour groups, and box/colour locked candidates can never fire because a group meets each box in one cell. Classic grades are unchanged. The ladder per unit set is cached.
- `puzzles:gen` takes `--variant jigsaw|rainbow`, writing to `content/sudoku/`.
- `scripts/format-content.ts` printed nested arrays as `[object Object]`; it now expands an object that holds arrays (needed for `regions`). A regeneration test covers a rainbow file.
- SPEC §Generated content: one clause about variants and `--variant`.
