## Notes

- Store in `src/puzzles/_shared/puzzle-keyboard/keyboard-store.ts` (`useSyncExternalStore`, server snapshot inactive). It tracks the hardware-key flag, the setting and the number of mounted pads.
- `usePuzzleKeyboard()` is active only when a `PuzzleKeyboard` is mounted, so a type that has not adopted the pad yet (everything until T115 and T116) keeps its system keyboard on phones. Without this, sudoku and the rest would have no input on touch.
- Touch matches the `touch` variant's query (`pointer: coarse` and `max-width: 47.999rem`).
- `forceVisible` on `PuzzleKeyboard` exists only for the kitchen-sink specimens.
- `SolveChrome` menu gets a checkbox item; the bottom slot gets `marginBottom` from `useKeyboardInset` when the setting is on. `useKeyboardInset` reads in `requestAnimationFrame` and resets to 0 when `visualViewport.height >= innerHeight`.
- `DigitGrid` needed no change: it renders `CellGrid`, which owns the `inputmode` logic.
- Docs: SPEC §4.5 bullet, `.claude/rules/puzzles.md`, `new-puzzle-type` skill.

## Deviations and follow-ups

- The pad is not yet rendered in any real solver (T115, T116), so the solve-menu toggle's effect on a pad is verified on the kitchen sink and its persistence on a solve page.
- AC7 names a `grid-blue` focus ring, but SPEC §6 (tokens table and brand checklist) makes focus rings `book-blue` through the `ring` token. The pad follows SPEC, so the ring is `#3A7FB0`.
