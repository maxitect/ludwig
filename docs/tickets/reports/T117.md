## Notes

- Tap targets: `touch:` classes on Button (`default`, `sm`, `icon`), Toggle (`default`, `sm`), the sheet close button (which fixes the mobile menu's own close), the solve back link, cipher key slots, book-cipher reference buttons and inputs, crossword clue rows and rota tokens. Gear swap buttons are `Button size="sm"`. The uncapture tray was already 48px.
- Rota tokens are 44px on squares about 41px wide, so they overlap neighbours by a pixel or two.
- Crossword pad keys are exempt from 44px on width (SPEC §6.7 says so). Ten keys across a 390px phone cannot be 44 wide.
- Chess tap uses only `onSquareClick`: react-chessboard v5 reports the piece in it and fires it for both occupied and empty squares, so `onPieceClick` would double-fire. It shares `drop` with the keyboard path. Tapping the picked square cancels.
- Android Backspace: native `beforeinput` listener on the hidden input (React's `onBeforeInput` does not carry `inputType`). A flag set by a Backspace/Delete keydown and cleared on keyup stops a physical key erasing twice.
- Real WebKit bug found by the new iphone project and fixed: T114/T115 used `onPointerDown={preventDefault}` to keep focus on the grid, and WebKit then never fires `click` on touch, so the crossword clue bar, pad and action row did nothing on iPhone. They now use `onMouseDown`, which keeps focus without suppressing click. The `crossword-mobile` specs, which failed 6 of 7 on `iphone`, now pass there and on `mobile`.
- Under parallel load against the dev server two Chromium specs (`gear-train` hub, `gears-layout`) timed out once and passed on rerun; unrelated.
- SPEC §6.7 gains "Tap targets" and "Touch input" bullets.

- Sign-in smoke: dropped by the implementer, restored in review. Sign-in fails only on the branch alias URL, not on the deployment URL that the preview job uses; see Review.
