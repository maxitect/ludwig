## Deviations and follow-ups

- **Network first with no timeout, not stale-while-revalidate, for HTML navigations.** SWR served the cached signed-out `/` to a signed-in user (found by the first run of test 3). The review removed the 8 s timeout for the same reason, so on a very slow link the page waits for the network, and the cache opens only when the network fails. This gives up part of the ticket's "bad connection" goal.
- **RSC is not cached (review).** The ticket asked for separate RSC entries. `pages-rsc` could never store anything, and the prefetch cache held 100+ entries of up to 280 KB with no offline value. A failed client navigation falls back to a document navigation, which the HTML cache serves.
- **Cache admission by guest marker.** The worker cannot read the HttpOnly session cookie, so a page is stored only if its body contains the opening tag `<div data-guest-menu=""` (added to `GuestMenu`).
- Worker is served at `/serwist/sw.js`, not `/sw.js` (AC6 allows the Serwist route).
- Page caches are deleted on service worker activation so no old shell survives a deploy.
