## Deviations and follow-ups

- **Network first, not stale-while-revalidate, for HTML and RSC navigations.** SWR served the cached signed-out `/` to a signed-in user (found by the first run of test 3). Network first with an 8 s timeout falls back to the cache only offline or on a slow link. The prefetch cache stays stale-while-revalidate because prefetches are the static shell and cannot hold session data.
- **Cache admission by guest marker.** The worker cannot read the HttpOnly session cookie, so a response is stored only if its body contains `data-guest-menu` (added to `GuestMenu`). It fails closed: RSC navigation responses that omit the header layout are simply not cached.
- Worker is served at `/serwist/sw.js`, not `/sw.js` (AC6 allows the Serwist route).
- Page caches are deleted on service worker activation so no old shell survives a deploy.
