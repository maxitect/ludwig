## Script-tag error: cause and fix

For a `notFound()` thrown in a page's shell, Next's error recovery (`node_modules/next/dist/server/app-render/app-render.js`, `getErrorRSCPayload`) sends `<html id="__next_error__"><head></head><body>` with no app markup, in both `next dev` and `next start`, and the client renders the whole tree, root layout included. React then creates the two inline `<script>` elements on the client, which never execute, and React DOM's development build logs "Encountered a script tag while rendering React component" (`react-dom-client.development.js`, `case "script"`). The production build creates the same inert scripts but has no warning.

`InitScript` returns `null` when `typeof window !== "undefined"`. Server HTML still carries both scripts in `<head>`, so they run before first paint, and React 19 skips the unmatched `<head>` tags during hydration (no hydration warning on `/`, `/puzzles`, `/puzzles/anagram`, a solve page, `/settings`). On the error shell no script element is created, so nothing is logged. `next/script` `beforeInteractive` was rejected: it doesn't block hydration, so it can flash the wrong theme.

## Deviations and follow-ups

- Follow-up (framework behaviour, not changed here): a `notFound()` from the type or solve page is served as Next's `__next_error__` shell and rendered on the client. Before JS loads the page is blank with no theme (`/puzzles/anagram/nope` with bundles aborted: `{"theme":null,"rm":false,"bg":"rgba(0, 0, 0, 0)"}`), and without JS it stays blank. Status is a real 404 and the themed page appears after hydration. The Next 16 docs (`04-functions/not-found.md`, "Calling notFound() after streaming has started") point at checking the resource in `proxy` for a server-rendered 404. That would put a DB lookup in the proxy, which `CLAUDE.md` limits to optimistic cookie checks, so it needs a decision; worth a ticket if no-JS 404s matter.
