## Deviations and follow-ups

- Previews are drawn on the `paper-sheet` surface in both themes, with `fill-paper`, `fill-ink` and `stroke-ink` classes. These don't match the `raw-tokens` patterns, so no allowlist change was needed. T120's surface treatment can be revisited when it lands.
- The pictogram preview draws `/glyphs/<key>.svg` through `<image>`; those files are black strokes, correct on the paper frame.
- Shelf thumbnails call `getPuzzlePayload` (`"use cache"`, tag `puzzles`), one cached entry per puzzle, since `load` is per puzzle. The shelf has no per-puzzle batch query.
- Every thumbnail sits in its own `Suspense`, with an empty paper frame as the fallback.
- The `puzzles:verify` and `registry-imports` guards still hold: previews are separate from the server registry and import no client code (`PieceGlyph` is a plain SVG component).
- `/gears` "Today's diagram" card has no thumbnail; the ticket names shelf cards only.
- T060 (cctv-maze) landed on `main` during the work, and the `previews` map must list every registered key, so this PR also ships `src/puzzles/cctv-maze/preview.tsx` (walls, cameras, start and exit). T130 need not do it. The wedge drawing shared with sightlines lives in `_shared/preview/sight-wedge.tsx`. `registry.ts` conflicted on rebase and the `modules` const now includes `cctv-maze`.
- Added the preview item to the scope of the new-type tickets T085 to T091 and T094 to T098. T092 and the generator tickets add no type and change no payload, so they are left alone. T084 and T093 change the sudoku payload, so review added an item to extend the sudoku preview.
- `.claude/rules/puzzles.md` and the `/new-puzzle-type` skill now list `preview.tsx`.
- No SPEC edit.
