## Decisions

- One name, `wrongParts`. Each type exports a `wrongPartSchema` (sudoku and futoshiki `{ row, col }`, logic grid `{ first, second }`); `PuzzleSchemas` has it optional and `WrongPart<S>` derives the type, so no hand-written union.
- Logic grid: correctness is still computed from every differing category pair, but only pairs where the answer links items are named, so an unlinked pair is never revealed.
- UI: `SolveChrome` stores `wrongParts` from a failed full check, passes them to the solver, and clears them on the next `onStateChange` and on Reset. Highlight is a dashed `ludwig-red` frame (pattern, not colour alone) plus the accessible-name label, in `CellGrid` (`wrong` prop, used through `DigitGrid`) and `MarkGrid`.
- No `attempt_hints` row is written by a full check.
- SPEC §4.1, §4.5 and the three §7.4.4 entries updated (gear-train's "as for sudoku" wording adjusted).
