## Deviations and follow-ups

- Migration `drizzle/20261009232818_drop_rota_attempt_instigator`: drops FK `rota_attempts_instigator_fk`, then the column.
- SPEC §7.4.4 updated (the rota attempt row and the Opening gambit paragraph).
- No code changes were needed outside `tables.ts`, and no test named the attempt column.
- **Single-step rollout is not safe** (see Review). The ticket note assumes Drizzle inserts only the columns it is given. It doesn't: `buildInsertQuery` lists every non-generated column and sends `default` for the missing ones. The code on `main` (`module.ts:155`, `tx.insert(rotaAttempts).values({ attemptId })`) therefore emits `insert into "rota_attempts" ("attempt_id", "puzzle_id", "instigator_worker_id") values ($1, default, default)`, and that fails against the new schema.
