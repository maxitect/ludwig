## Deviations and follow-ups

- **Split into two steps (user decision, 2026-10-10).** The first version of this PR dropped the column in a migration. That isn't backward-compatible (SPEC §7.7). Drizzle's insert names every column it doesn't generate and sends `default` for the missing ones. The code on `main` (`module.ts:155`) therefore sends `insert into "rota_attempts" ("attempt_id", "puzzle_id", "instigator_worker_id") values ($1, default, default)`, which fails once the column is gone.
- This PR is now step (a): the column is removed from `tables.ts`, with no migration. Step (b) is the new ticket `docs/tickets/T141-drop-rota-instigator-column.md` (README M4 row, todo, depends on T132). It starts only once T132 is in production.
- The latest Drizzle snapshot still has the column, so the next `pnpm db:generate` produces T141's drop. T141 must be the next ticket to generate a migration, or the drop will land inside another ticket's migration. The orchestrator should hold other migration tickets until T141 is done, or that ticket should delete the drop from its generated SQL.
- SPEC §7.4.4 updated (the Opening gambit paragraph and the rota attempt row) to say the column is out of the schema and that T141 drops it.
- The earlier drop migration was applied to `ludwig_t132`, `ludwig_t132_test` and the preview branch. On all three I re-added the column and its FK and deleted its row from the migration journal, so each matches `main` again.
