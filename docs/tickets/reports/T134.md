## Notes

- No content file names a volume today (only `content/lookups.ts` defines volumes), so no content file needed a position. The AC2/AC3 checks used temporary edits to two anagram files, reverted before finishing.
- The category page shows volume cards with puzzle counts only and lists puzzles by title, so there is no per-volume list to reorder. The only other volume ordering, the shelf representative puzzle, now sorts by volume, position, then slug.
- Migration approach: add the nullable column, backfill `row_number() OVER (PARTITION BY volume_id ORDER BY slug)` (today's order), then add the unique constraint and the CHECK, so it succeeds before the seed runs. The previous deploy never inserts puzzles with a volume at runtime, so it keeps working.
- Swap safety: not `DEFERRABLE`. The seed writes each puzzle in its own transaction, so a deferred constraint would not help across them (and drizzle cannot declare it). Instead, inside each puzzle's transaction, `writePuzzle` first moves any other puzzle holding the wanted `(volume, position)` to the negative of its position; that puzzle takes its own position when its file is seeded. Covered by a seed test that swaps two positions. A displaced puzzle whose file fails keeps a negative position until the next good seed.
- "Next in volume" now reads the volume's published puzzles in position order and takes the first with a higher position.
- Schema also requires `volumePosition` to be absent when no volume is named. SPEC §4.5, §4.6 and §7.4 updated.
