## Deviations and follow-ups

- **User overrides applied:** templates use React Email, and the ticket's "Out" line and Templates bullet were updated. I used `react-email@6.11.1` (pinned), because `@react-email/components` is deprecated on npm ("Package no longer supported"). It supports React 19 and bundles `render`. Layout is `src/lib/email/layout.tsx`, token hexes `src/lib/email/tokens.ts`, templates in `src/lib/email/templates/`, sender `src/lib/email/send.ts`. All are `server-only`. The raw-token guard only scans `src/puzzles` and `src/components`, so no allow-list entry was needed.
- **Sender:** `EMAIL_FROM="Ludwig <auth@noreply.ludwigpuzzles.com>"` (default in `src/env.ts`), and every email is signed off "Ludwig". I added `EMAIL_FROM` to Vercel for Production and Preview with the CLI. `RESEND_API_KEY` was already there. An empty `RESEND_API_KEY` is treated as unset so local runs can force the console fallback.
- **E2E regression (needs a follow-up ticket):** `e2e/helpers/auth.ts` `signUp` relied on auto sign-in, so every Playwright spec that signs up now stops at "Check your inbox". The specs run against previews and can't read mail. The fix needs a test-only verification path, e.g. a seeded verified account or a gated test endpoint. I did not invent one. Not done here.
- **Cookie cache:** `session.cookieCache` (5 min, existing config) means another browser whose session was revoked by a reset or password change can look signed in for up to five minutes, although the `session` rows are gone. Left as is.
- **SPEC edits:** §2.2, §7.3 (config, new Email subsection, rate limits, the v1.1 paragraph removed) and §10 decision 5. `.claude/rules/auth.md` updated to match.
- **Existing test changed:** `src/db/db.test.ts` relied on sign-up auto sign-in. It now marks the user verified and signs in.
- During local checks the worktree `.env.local` held the real Resend key. One early sign-up (ann@test.local) went through Resend before I forced the console fallback. The key was never read or printed.
- The new pages work behind the sign-in redirect flow, but the verify link on a protected preview needs the Vercel share link or a bypass cookie. Not checked on a deployed preview yet.
