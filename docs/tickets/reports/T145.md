## Deviations and follow-ups

- Decisions taken without the user (they are away):
  - The migration deletes all `spot-difference` puzzles (cascading to their weekly slots and every attempt, saved finds included) before altering the tables, because `scene_key` is NOT NULL and the old rows have no scene. This is the pre-launch data the ticket says can go. It is destructive on production, so the migration is flagged for the person merging.
  - `content/weekly.ts` had ten slots on the five removed puzzles. They now hold existing crosswords and anagrams, avoiding repeats within a week. T146 should put the real scenes back.
  - The fixture is `fixture-clandon`: John Preston Neale's 1824 engraving of Clandon House (public domain, Wikimedia Commons), three edits made by cloning patches (a chimney painted out, the pediment roundel painted out, a sheep replaced by grass). Its source is only 592px wide, so the 1600px prepared copy is upscaled.
  - "Drawn in the ink token in both themes": the mask paints the surface's foreground, so in Ink the engraving is light lines on dark (a negative), as AC5 requires no paper box. T146 art should be checked in that theme.
  - `verify` hooks may now return a promise (`PuzzleTypeModule.verify`, awaited in `verify-puzzles.ts` and `time-verify.ts`), because the pixel diff reads WebP files with `sharp`. `sharp` is a new devDependency, imported dynamically inside `verify`, so it never enters the app bundle.
  - Pixel diff compares mean ink per 8px block, not pixels. At the shipped alpha quality the lossy WebP flips single pixels between identical areas, so a pixel diff joined the whole scene into noise. A cluster of at least 2 changed blocks counts. Regions need a margin of at least one block (8px) around an edit. Documented in `verify.ts` and SPEC 7.4.4.
  - `prepare-scene.ts` uses fixed levels (no per-image normalise) so the pair maps identically, and alpha quality 15 to keep the pair near the 300 KB budget (alpha 80 gave 720 KB per image).
  - `spot_difference_attempts` also gains a redundant `puzzle_id` with its own fill trigger, mirroring `word_search_attempts`, so the found rows can carry the composite FK.
  - The preview wraps the scene in `<svg><foreignObject>` so it stays an SVG as `previews.test.tsx` and the preview rule require, and reuses the exact mask.
- The altered scene loads only when first shown on touch, so toggling to Right can briefly show an empty frame on a slow connection. Not changed here.
- Dropping columns in the migration is not backward-compatible with the previous deploy for the few seconds the old build is live; acceptable pre-launch.
- SPEC edits: section 1.2 (engraved scenes), 2.3 row, the "Generated content" bullet (gears only), 7.4.4 (spot-difference row rewritten), 7.4.5 (two new redundant `puzzle_id` rows). PLAN row for spot-difference updated.
- The shelf preview (`preview.tsx`) masks the full 1600px `original.webp` (143 KB) per scene. That is the same file the solve page fetches, so it is cached, but with T146's several scenes a shelf page would load one full image per tile. T146 should consider a small thumbnail asset from `prepare-scene.ts`.

No spot-difference test failed in any run. Root causes, from the Playwright traces:

- **wrong-parts (product bug).** Filling the last cell auto-checks (`digit-grid.tsx` `requestCheck`). The spec then clicks Check, which Playwright clicks once the button is enabled again, so a second check of the same answer goes out. The spec erases the mistake while that check is in flight. The trace shows the second `checkAnswer` POST ending at 629153 ms and the Backspace at 629142 ms. The stale wrong result then re-marked 3 cells on a grid that had changed. Fix: `solve-chrome.tsx` counts edits and drops a wrong result for an answer edited since it was sent. A correct result is still applied, because the server has already recorded the solve. New unit test: "drops a wrong result for an answer edited while it was checked" fails without the fix (it finds the `Not quite` notice) and passes with it.
- **napkin-maths (spec race).** The spec pressed Enter on a wrong answer, then asserted `Solved in` absent at once. That assertion passes instantly, so it did not prove the check had finished. It then typed the right answer. The debounced save went out while the wrong check's transition was still pending, so the final Enter landed while `pending` was true. `check()` ignores Enter while a check is pending, as the disabled Check button does, so no third POST was sent (the trace shows 3 POSTs, none after the last Enter). Fix: the spec now waits for `Not quite. Keep going.` before editing. The assertion is unchanged.

Design change: on touch, both scenes are now stacked (original above altered) instead of the Left/Right toggle, so both images load. Desktop is unchanged. `e2e/spot-difference-mobile.spec.ts` now asserts that both scenes are visible and stacked and that there is no radio.
