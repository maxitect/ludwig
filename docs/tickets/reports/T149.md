## Design decisions

- **Registered: troix and kakuro** (`src/config/daily-types.ts`). Troix is by far the fastest. Railroad was also fast, but sudoku + troix + kakuro + railroad took about 193 s locally, too close to the 300 s limit if production is slower, so it was left out. With three types the first run is about 123 s locally, 2.4x headroom.
- **First backfill:** the cron writes missing dates only and each date is its own transaction, so a killed run loses nothing. Review added a 270 s budget, because production is projected to need about 327 s (see AC2): the run now ends with a 200 and `pending` counts rather than a killed function. Dates run from today forward, so today's daily is written first.
- **Player wiring:** a daily is an ordinary published puzzle (slug `daily-<type>-<date>`, `published_at` at London midnight), so the existing puzzle page, catalogue and future-date 404 apply unchanged. Sudoku has no extra daily UI either, so none was added.
- **`puzzles:verify` fix:** kakuro's served payload derives its clues from the solution, so comparing the stored payload to `payloadSchema.parse(content)` failed on every kakuro daily (unrecognized key `digit`). The module now owns this: an optional `payloadFromContent` hook on `PuzzleTypeModule`, which kakuro's `load` shares and `verifyDailyRows` calls. Troix's payload parses straight from its content, so it needs no hook.
- SPEC §daily paragraph updated to name the registered types.
- `puzzles:verify` with 1098 daily rows takes 133 s locally. CI never generates dailies (`grep gen-daily .github` is empty), so its `db` job does not pay this: it ran in 1m22s on this PR, within its 20-minute limit.
- **Daily shelf:** the type page lists the 14 newest dailies on a "Daily" shelf above the curated puzzles. This also changes sudoku. Older dailies keep their URLs and still count towards the Complete badge, as they do on `/puzzles`. SPEC updated.

## Deviations

- Registered two new types, not the ticket's maximum of three, to keep the first run safe. Recommended option, per the overnight instruction.
- Follow-up: older dailies have no catalogue listing, so an archive page is a possible later ticket. The Complete badge can't stay earned once a new daily appears, as with sudoku since T111.
- Production check after merge: the first 00:10 UTC run. Read `daily_puzzles` counts on Neon `main`; kakuro may need a second night.
