## Design decisions

- **Routing.** `src/proxy.ts` rewrites `/` to `/desk` only when a Better Auth session cookie is present (matcher `has` on the two cookie names, so signed-out landing requests never invoke the proxy). The landing stays fully static, with no new prerendered pages or ISR writes (`/desk` is dynamic). `/desk` reads the session itself (`getCurrentUser`, then `getDesk` calls `requireUser`); a stale cookie renders the landing, so there is no redirect loop. The matcher must be literal: a `.map` spread made Next match every path.
- **Continue is one query.** Each puzzle module now exposes `attemptRoot` (its `<type>_attempts` table, which has a row exactly when state is saved). `getDesk` builds one `attempts.id in (select ... union all ...)` over the registry inside a single RQBv2 `findMany` (unfinished, newest `last_saved_at`, limit 8). No per-attempt or per-type calls. Chosen over a per-attempt `hasAttemptState`.
- **Migration** `attempts_last_saved_at`: add nullable, backfill `coalesce(completed_at, started_at)`, set default `now()`, then NOT NULL. Backward compatible (an old deploy's inserts take the default).
- Today's dailies are one RQBv2 query on `puzzles` (daily or gear daily for the London date); this week's pair reuses the cached `getWeeklySchedule`. "Solved this week" is computed in SQL with the London week start.
- The "Desk stub in `_components/desk.tsx`" did not exist on main; the component is new.
- Slots for T154, T161 and T160 are sibling sections in `Desk`, in the fixed order.
