## Changes

- `scripts/top-up-dailies.ts` / `pnpm puzzles:top-up-dailies`: gears then each `dailyTypes` type, today (London) through today + 400, one line per type with created, present, pending and seconds. Shared deadline (default 900 s, `TOP_UP_BUDGET_SECONDS` overrides); exits 0 when the budget stops it. Uses `DATABASE_URL_UNPOOLED` like the other generator scripts.
- `gear-dailies.ts` `generateDailies` gained an optional `deadline` (same as the grid one); behaviour otherwise unchanged. `puzzles:gen-daily` / `gen-gears` kept as the per-type forms.
- `vercel.json`: build command now includes the top-up; `crons` removed. Both cron routes deleted (they had no tests of their own).
- `verify-puzzles.ts`: `verifyDailyWindow` fails a daily table (gears, or a `daily_puzzles` type) with rows whose latest date is under 180 days ahead. Chosen: skip empty tables, rather than generating a window in the `db` job, because verify costs about 130 s per 1100 rows and CI has no dailies.
- Docs: SPEC §4.6, daily diagram and daily grid paragraphs, §7.7 build command, CRON_SECRET row; `generators.md`; CLAUDE.md commands; superseded notes on the T078, T111 and T149 reports. The README status was not touched.
- Cache Components, prerender count and ISR writes untouched (`generateStaticParams` unchanged; T159's 14-newest rule still applies).

## Build timing

Local cold database (no dailies besides the seed), 400 days: gears 4.4 s, sudoku 48.2 s, troix 11.6 s, kakuro 132.6 s: about 197 s. Production is about 3.8x slower, so a fully cold production run is about 750 s, inside the 900 s budget and far inside Hobby's 45-minute build limit. Production today is about 35 days short, so the first build writes roughly 35 days per type plus kakuro's 105 missing, and every later build writes only the days since the previous deploy (seconds). Note the build runs on one worker and the budget only stops the top-up, so worst case adds 900 s to a build.
