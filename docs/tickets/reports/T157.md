## Decisions

- Storage: two nullable timestamps on `user_settings` (`favourites_digest_at`, `nudge_sent_at`) rather than a `favourite_digests` table. Only the latest value is ever read, a table would grow one row per user per day for no query, and `favourites_digest_at` doubles as the cursor ("published after the last digest") and the once-a-day guard. It is set to now when the box is ticked (in `updateUserSettings`), so nobody gets a backlog from before they opted in. No trigger was needed (the `/db-trigger` skill says side effects belong in app code), so the migration is plain DDL: `user_settings_email_notifications`.
- The cursor records the last digest *run* (also advanced when there was nothing to send), not only the last email, so a second call the same London day selects nobody.
- Schedule: UTC crons `0 8 * * *` and `0 17 * * *` = 09:00 and 18:00 London in summer, 08:00 and 17:00 in winter (and Hobby fires within the hour). No hour check in the route. Noted in SPEC §7.7. "Today" inside the selection is always the London date.
- Guard test `desk-charts.test.ts` ("no stored stats") matched `notify_streak` by name; I allowlisted exactly that column (a preference, not a stat). I named the other column `nudge_sent_at` to avoid the pattern.
- Failed sends are not recorded, so the next call retries them. Sender is `EMAIL_FROM` (default `Ludwig <auth@noreply.ludwigpuzzles.com>`). Only verified addresses are emailed. `List-Unsubscribe` headers are not added, because `send.ts` has no header option (follow-up).
- SPEC §7.3 (email kinds), §7.4 table line and §7.7 (crons, `CRON_SECRET`) updated.

### Findings and fixes

1. **Unsubscribe GET changed state** (orchestrator decision). Mail scanners that prefetch links would silently unsubscribe players. Removed `src/app/api/unsubscribe/route.ts`; the email link is now `/unsubscribe?token=` (`src/app/(marketing)/unsubscribe/page.tsx`), which verifies the signature without a session and without touching the database, and shows one Unsubscribe button. The Server Action `src/lib/actions/unsubscribe.ts` re-verifies the token, clears the setting and redirects to `/unsubscribed`. A bad or missing token shows "This link is not valid." with no button; nothing reveals whether an address is registered. SPEC §7.3 updated. Commit `9a679c3`.
2. **Milestone note missed when the player had already solved today.** The query required no solve today, so a player who solved before the 08:00 UTC run (streak now N+1) never got the note. It now subtracts today's solve from the current streak. Red first: the new case in `notifications.test.ts` failed with `expected 2 to be 3` sends, then passed. Commit `88d7dbe`.
